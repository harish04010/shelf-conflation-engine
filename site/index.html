Shelf Conflation Engine

Turns noisy wearable-camera detections from three store walk-throughs into one versioned, verified record per shelf slot. Regex and rules go first, agreement within the same slot second, and an LLM gets only what's left.

Code on GitHubExplore the storev1 vs v2

Steps

  1. ContractUpgrade firmware schema v1 and v2 to one record; quarantine what breaks the contract.
  2. FilterRegex drops price tags and shelf signs before they become fake products.
  3. BarcodeValidate check digits, normalize EAN-13, repair one-digit misreads when the text agrees.
  4. RulesParse pack sizes, narrow by aisle and brand, fuzzy-match text, guard variants, demand a clear lead.
  5. ConflateCluster sightings by position into slots; settle ambiguous reads by what the slot agrees on.
  6. LLM or reviewOnly the residue, shown a shortlist, with the answer checked against it.
  7. PublishGolden records with lineage, written to a versioned run folder with a manifest.

Where each detection was resolved

Each tier is cheaper and more certain than the next. Accuracy is checked against the simulator's ground truth, which the pipeline never sees.

    The edge firmware changed between passes 2 and 3: renamed fields, centimeters instead of meters, and the barcode moved into an object. Both versions are upgraded to one canonical record.

    Limits

    • The data is simulated. Brands are fictional and every barcode has a valid check digit; public product databases weren't reachable from the build environment. The simulator's noise (OCR errors, misreads, duplicates, schema change, shelf changes) is described in the README.
    • The LLM tier hasn't been run. Without an API key, ambiguous detections go to a review queue. Costs are estimates from prompt length at assumed per-token prices.
    • A missed sighting looks like an empty shelf. Some flagged gaps are real stock-outs and some are one camera miss; telling them apart needs another pass.
    • New items without a barcode usually end up in review rather than being recognized as new, because their text resembles existing products. That's the safe failure.
